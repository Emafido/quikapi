# QuikAPI — Launch Plan

## How to Get the First 10 Users

### The Reality
QuikAPI solves a specific, immediate pain for a specific person: the frontend developer who needs a backend right now. The launch strategy is built around finding that person where they already are and showing them the product working — not describing it.

---

### User 1–3: People I Already Know

Before any public launch, send a personal message (not a group blast) to three developers I know personally who have complained about backend setup in the past.

Message template:
> "Hey — I built something this week I think you'd actually use. It turns a sentence into a live API in about 30 seconds. Can I send you the link? No pitch, just want to know if it's useful."

Personal outreach converts better than any post. These three become the first testers and the first word-of-mouth.

---

### User 4–6: Nigerian Developer Communities

Post in these specific places with a screen recording (not a text description):

- **GDG Lagos WhatsApp group** — developers actively building, high engagement
- **She Code Africa Discord** — large community of African developers
- **Devcenter Square Slack** — Lagos tech community, builders and founders

Post format:
> "Built this over the past week — you describe an API in plain English and it gives you live endpoints you can actually hit. Took me 30 seconds to demo. Link: [url]. Feedback welcome."

Attach the 2-minute screen recording. Video posts in communities get 3-5x more clicks than text posts.

---

### User 7–8: X (Twitter)

Post the demo thread:
- Tweet 1: The hook ("what if you never had to wait for a backend again?") + screen recording
- Tweet 2: Feature breakdown with the #BuildQuik hashtag
- Reply to every comment within the first hour

Tag relevant accounts:
- @QuikDB — they'll likely repost it (they have incentive, it's their platform)
- @devcenterlagos
- @gdglagos

Post time: Tuesday or Wednesday, 9–11 AM WAT. Avoid weekends.

---

### User 9–10: Reddit + Dev.to

**Reddit:**
Post in r/webdev with title: "I built a tool that turns plain English into a live REST API — describe it, deploy it, done"

Rules for Reddit:
- Lead with the problem, not the solution
- Show the screen recording in the first comment
- Respond to every reply within 2 hours of posting

**Dev.to:**
Write a short article: "How I built a live API generator in 10 days for a hackathon"
- Cover the problem, the approach, one interesting technical decision (the JSON file store tradeoff)
- Link to the live app at the end
- Dev.to has a built-in audience of developers looking for tools exactly like this

---

### The Multiplier: QuikDB Platform

Because QuikAPI is deployed on QuikDB and built specifically for their hackathon, there's a natural distribution channel already in place:
- QuikDB will likely feature it in their newsletter or social posts
- The BuildQuik finale audience is exactly the target user
- Being in the top 5 at the finale = live demo in front of 200+ developers

The finale is the real launch moment. The goal of users 1–10 is to have real usage data and genuine feedback to reference during the demo.

---

### Launch Checklist

- [ ] Personal outreach to 3 developers (Users 1–3)
- [ ] Post in 3 Nigerian developer communities with screen recording (Users 4–6)
- [ ] X thread with demo video + #BuildQuik (Users 7–8)
- [ ] Reddit r/webdev post (User 9)
- [ ] Dev.to article (User 10)
- [ ] Reply to every comment within 2 hours of each post
- [ ] Tag @QuikDB on every post
